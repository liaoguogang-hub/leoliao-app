# v1.34.0 — 重索引改为"从全文 note 重切"(不依赖 bytes)

> **代号**: `reindex-from-notes` · 2026-09-04

## 🐛 真根因(从 logcat 发现)

```
[file-opener] PDF 文字提取完成, 5065 字 / 9 页 / 0 空页   ← 提取其实成功
[reindexAll] no bytes for 住友&京东健康 ....pdf            ← 但重索引拿不到 bytes!
[reindexAll] no bytes for 生命3.0.epub                    ← EPUB 也一样!
```

**真相**:
1. 用户看到的 "9 chunks" **不是 bug** —— 那份 PDF 只有 9 页,5065 字全部入库,每页 1 chunk = 9 chunks,正确
2. **真正 bug**:`reindexAll` 依赖 history 表的 bytes,但 **>512KB 的文件不存 bytes**(`HISTORY_LOCAL_SNAPSHOT_MAX=512KB` 设计限制)→ 住友 PDF / 生命 3.0 EPUB(都是几 MB)**永远无法重索引** → 它们一直是老数据

## ✅ 修复

`reindexAll` 重写:**从 notes 表拿已提取的全文重新切分**,完全绕开 bytes:

```ts
// 之前:拿 history bytes → 重新解析 PDF/EPUB(>512KB 失败)
// 现在:找 notes 表里 📕/📘 xxx.md 的 content → chunkDocument() → saveChunks + vectors
const note = allNotes.find(n => n.path === f.path + '.md');
const chunks = chunkDocument(f.path, note.content, { mode: 'paragraph-only', forceChunkSize: 500 });
await saveChunks(f.path, chunkRows);
await saveChunkVectors(f.path, vecRows);
```

**原理**:file-opener 早就把提取的全文存成 `📕 xxx.pdf.md`/`📘 xxx.epub.md` 进 notes 表 —— 重索引只需重切这个文本,不需要二进制。

## 📊 影响

| 项 | 之前 | 之后 |
|---|---|---|
| >512KB 文件重索引 | ❌ no bytes 跳过 | ✅ 从 note 重切 |
| 重索引速度 | 慢(重新解析 PDF/EPUB) | 快(纯文本切分) |
| 结果一致性 | 依赖首次提取质量 | 同首次提取(notes 就是提取结果) |

## ⚠️ 注意

- 如果某 PDF/EPUB **首次提取就失败**(扫描版),notes 表也没全文 → 依然无法恢复(需 OCR)
- 重索引用 paragraph-only,EPUB 会切成几百 chunks(章节内细切)
