# v1.26.0 — UX: Chunker 细粒度 + EPUB 可重索引

> **代号**: `chunker-fine` · 2026-09-04

## 🐛 用户反馈的根因

用户报告"chunker 切分粒度有问题":
- 生命 3.0 EPUB 只有 12 个 chunk,且集中在 3 章
- 8 章中有 5 章 KB 完全空白
- 根因:chunker 默认按 `## ` 二级标题切,EPUB/前言/目录/单章节(无标题)被切成 1 个超大 chunk

## ✅ 修复

### 1. `chunker.ts` 加 `paragraph-only` 模式

```ts
export interface ChunkOptions {
  mode?: 'heading' | 'paragraph-only';
  forceChunkSize?: number;  // paragraph-only 模式下每 N 字切一段,默认 400
}

chunkDocument(path, content, { mode: 'paragraph-only', forceChunkSize: 500 });
```

**算法**:
1. 按 `\n\n` 拆段落
2. 累加段落直到总字数 ≥ `forceChunkSize` 就 flush 一个 chunk
3. 单段 > 1.5x → 强制按字数切(防止超长段落)
4. chunk 间保留 100 字 overlap(同 heading 模式)

### 2. PDF/EPUB 索引自动用新模式

```ts
// PDF:每页当一段,forceChunkSize=500
chunkDocument(pdfId, fullDoc, { mode: 'paragraph-only', forceChunkSize: 500 });

// EPUB:同上,每章按字数细切
chunkDocument(epubId, fullDoc, { mode: 'paragraph-only', forceChunkSize: 500 });
```

效果:
- 30 页 PDF:从 1 个 chunk → ~20-30 个 chunk
- 100 章 EPUB:从 12 个 chunk → 100-300 个 chunk
- 搜索召回率预期提升 5-10 倍

### 3. `reindexAll` 支持 EPUB

之前 `reindexAll` 只支持 PDF 重索引(`__debugRenderPdf`),EPUB 直接被跳过。
现在加了 `__debugRenderEpub` 公开接口,EPUB 也能从 history bytes 重做索引。

## ⚠️ 注意

- 重索引后 chunks 数量 **+50%-300%**(典型情况)
- 大 EPUB(>5MB)重索引可能耗时 2-5 分钟
- 之前已经在 KB 里的引用可能失效(路径变了)— 但 `path+idx` 是稳定的,引用不会错
