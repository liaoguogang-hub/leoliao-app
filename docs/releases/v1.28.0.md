# v1.28.0 — 重索引稳定性:等待 indexingDone

> **代号**: `reindex-stability` · 2026-09-04

## 🐛 问题

`reindexAll` 调 `__debugRenderPdf`/`__debugRenderEpub` 时是 fire-and-forget(后台索引),旧代码**没等 indexingDone** 就开始下一个文件。结果:

- 大 EPUB(几十 MB)的 indexing 要 1-3 分钟
- 切换到下一个文件后,前一个的 indexing 还在跑
- chunks 表状态错乱

## ✅ 修复

`local-files-panel.ts` 的 `reindexAll`:

```ts
// 之前:不等
const file = await fileOpener.__debugRenderPdf(bytes, name);
// → indexingDone 后台跑,不等待

// 现在:等
const file = await fileOpener.__debugRenderPdf(bytes, name);
if (file.indexingDone) {
  console.log('[reindexAll] waiting indexingDone for', name);
  await file.indexingDone;
  console.log('[reindexAll] indexingDone resolved for', name);
}
// 给 webview 喘息
await new Promise(r => setTimeout(r, 200));
```

## 🎯 用户操作流程

1. 打开工具栏的 **📚 本地参考库**
2. 点 **🔄 重索引全部**
3. 进度显示:`⏳ 0 / 3 - 重建 生命3.0.epub`
4. **真等 indexingDone**(大文件可能要等 1-3 分钟)
5. 完成后 alert `✅ 重索引完成: 3 个文件`
6. **文件列表刷新**:每个文件的 chunks 数从原来变成 100-300+
