# v1.24.0 — Hotfix: Agent 死循环 + 收敛

> **代号**: `agent-converge` · 2026-09-04
> **类型**: Bug 修复(用户报告"Agent 跑了 5 步没结果")

---

## 🐛 用户报告的问题

打开本地 PDF / EPUB,等索引完成后,在 chat 里问"这本 PDF/EPUB 讲什么?" → Agent 跑 5 步后提示"Agent 跑了 5 步,没拿到最终答案"。

## 🔍 真实原因

按 v1.23.0 修复后,**Agent 应该能检索到本地文件**(`includeLocal=true`)。但用户报告问题**说明还有更深层的 bug**:

1. `MAX_STEPS = 5` 太少 — Agent 多步推理时 5 步不够
2. Agent 在 `kb_search` 返回空结果时,**会反复调同一个工具**(`kb_search("xxx")` → 空 → `kb_search("更精确")` → 仍然空),陷入死循环
3. 5 步走完,LLM 还在调工具,没机会返回最终答案
4. `fullAnswer` 只在"无 tool_call"分支赋值,工具循环结束时永远是空字符串
5. fallback 输出机械的"Agent 跑了 5 步,没拿到最终答案"——即使 LLM 已经输出过答案

## ✅ 修复

### Fix 1: `MAX_STEPS 5 → 8`
给 Agent 足够的多步推理空间

### Fix 2: stuck-loop 检测
- 记录每次工具调用签名 `(toolName, argsJSON)`
- **连续 2 次相同签名** → 主动中断,注入"立即给最终答案"提示,再调一次 LLM 强制收敛

### Fix 3: final-answer hint
stuck 时的强制提示词:
```
⚠️ 你已经连续 2 次调用同一个工具并得到相同结果。
**请立即给出最终答案**(不要再调用任何工具,直接用你已经看到的信息回答)。
```

### Fix 4: 优化 fallback
- 之前:`fullAnswer` 空 → 输出"跑了 N 步没拿到"+ 显示最后一条 messages(可能是 tool_result)
- 现在:用 **`lastLlmText`**(最后一次 LLM 输出,可能是 thought + 部分答案)替代
- 真没有 LLM 输出才用之前的"跑了 N 步"提示

### Fix 5: AgentContext 透传 `includeLocal`
保险起见,虽然 `agent.ts` 的 kb_search 默认 `true`,chat-panel 仍然把 `this.includeLocal` 显式透传过去
