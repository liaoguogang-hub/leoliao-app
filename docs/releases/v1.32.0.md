# v1.32.0 — Graph 渲染截断 + 回滚 + auto-wikilinks 全局上限

> **代号**: `graph-safety` · 2026-09-04

## 🐛 问题

1. **Auto-wikilinks 过度注入** — 真注入了 23940 条 wikilink,vault 严重污染
2. **Graph "一直构建中"** — 23940 条边要画 SVG,webview 渲染瓶颈
3. **Graph 节点数显示 941,但应该有 1200+** — 缺失 ~300 孤儿笔记

## ✅ 修复

### 1. auto-wikilinks 全局上限(默认 500)

```ts
maxPerNote?: number;  // 8(之前 20)
maxTotal?: number;    // 500(新)
```

不再让"全 vault 扫一遍"成为可能 — 命中 500 就停。

### 2. Auto-inject 注入 marker(方便回滚)

```html
<!--@leoliao:aw:123:note/path.md-->[[笔记名]]
```

HTML 注释渲染时不可见,但能被正则识别。

### 3. `revertAutoInjectedWikilinks()` — 一键回滚

扫所有 vault 笔记,识别 `<!--@leoliao:aw:N:...-->` marker,只删这种配对的 wikilink。**不会**误删用户手写的。

### 4. Graph 边数渲染截断(800)

```ts
const MAX_RENDER_EDGES = 800;
if (edges.length > MAX_RENDER_EDGES) {
  renderEdges = [...edges].sort((a, b) => b.value - a.value).slice(0, MAX_RENDER_EDGES);
}
```

按权重排序保留 Top 800,防止 webview SVG 渲染崩溃。

### 5. Graph 加 ↩️ 回滚注入按钮

一键调用 `revertAutoInjectedWikilinks()`,清掉之前注入的 23940 条污染。

### 6. loading 卡死保险

`runAutoWikilinks` 的 `finally` 块强制 `loading=false`,防止 buildGraph 报错时 UI 永远转。
